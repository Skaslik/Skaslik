 ЦЕЛЬ
--------------------------------------------------------------------------------
 Единое семейное приложение для двоих (я и жена). Общий календарь с
 уведомлениями, вкладка «Файлы» — общие документы (хранение на
 Яндекс.Диске), копилки, карты лояльности. Android в первую очередь,
 iOS потом.

 Принципы:
   - Локальная пара (2 человека), не масс-маркет. Ни монетизации, ни рекламы,
     ни аналитики. Только качество и надёжность.
   - Offline-first: всё состояние живёт на устройстве, интернет нужен только
     для синхронизации между двумя телефонами.
   - Приватность: zero-knowledge-подход — ядро шифрует данные, сервер (когда
     будет) не видит содержимое.
   - Фейк-режим (конфиденциальность): тройное нажатие на монограмму
     открывает фейковый калькулятор, чтобы не было видно, что это «МС».


 АРХИТЕКТУРА
--------------------------------------------------------------------------------
 Проект — моно-репозиторий из двух пакетов + инфраструктура:

   core/        Чистый Dart, без Flutter. «Ядро» — вся логика, крипто, CRDT.
                Тестируется `dart test` (headless, без устройства).
   ms_app/      Flutter-приложение (UI + плагины). Импортирует core как
                path-зависимость. Тестируется `flutter test` / `flutter analyze`.
   android/     (в ms_app) — Android-скелет для сборки APK.
   fetch_all.sh Одинарный скрипт сборки: Flutter SDK + pub + тесты + (опц.)
                JDK + Android SDK + APK + headless-эмулятор.
   .github/     CI (analyze + build appbundle на ubuntu).

   Синхронизация — local-first + CRDT:
     - Каждый домен (календарь/копилки/карты/...) хранится как CRDT-реплика
       (op-log + tombstones + Лампорт). Два телефона сходятся сами, без
       сервера-арбитра (Last-Write-Wins на поле).
     - Локальная персистентность — JSON-файл на устройство (local_file).

   Ключевые решения (закреплено, менять только через CHANGELOG):
     - Кроссплатформа: Flutter 3.x (Dart) — один код на Android и iOS.
       APK не работает на iPhone: для iOS нужен отдельный IPA (сборка с
       того же исходника, нужен Mac / macOS runner + Apple-аккаунт).
     - Стейт-менеджмент: Riverpod.
     - Локальное хранилище: local-first JSON (позже Drift/SQLite).
     - UI: Material 3 + своя дизайн-система (ms_theme), тема «warm» по иконке.
     - Безопасность: zero-knowledge E2E в ядре (crypto/pairing/seed_phrase),
       локальный PIN/биометрия (local_auth), фейк-калькулятор.
     - Целевой Android: minSdk/targetSdk/compileSdk — значения Flutter-дефолта
       (compileSdk 35, build-tools 35.0.0, JDK 17/21).

 ВКЛАДКА «ФАЙЛЫ» — ОБЩИЕ ДОКУМЕНТЫ НА ЯНДЕКС.ДИСКЕ (требование пары)
--------------------------------------------------------------------------------
 Суть: отдельный раздел приложения, где лежат наши общие документы.
 Сценарий: я загружаю документ (договор, чек, паспорт, PDF с телефона или
 с диска) → он всегда доступен и мне, и жене, с любого устройства, когда
 нужно. Хранилище байтов — Яндекс.Диск: не строим свой сервер, файлы
 «проживаются» в общем облаке пары, приложение — это «живая папка».

 Что уже есть:
   - core/integrations/yandex_disk.dart — готовый клиент (OAuth PKCE,
     chunked upload c resume, listing).
   - Экран «Файлы» (docs_screen) — работает как local-first реестр
     метаданных: название, теги, список. Кнопка «Файл» добавляет запись.

 Что сделать, чтобы требование закрылось полностью:
   1. OAuth-подключение к Яндекс.Диску в приложении: авторизация через
      браузер (app redirect), refresh-token в flutter_secure_storage,
      авто-renew, обработка 401/429 с backoff. Одинаковый сценарий на
      обоих телефонах (каждый логинится в свой аккаунт Яндекса; доступ к
      папке пары — общие диски/папка с доступом, решение по модели
      «общая папка» зафиксировать в PLAN.md секции 5.4).
   2. Загрузка: выбор файла (file_picker/SAF) или камера-скан (серия
      страниц → PDF) → шифрование (AES-256-GCM, ключ = HKDF(k_docs,
      file_id)) → chunked upload на Яндекс.Диск в папку
      /Семья/<pairing_id>/Документы/ → прогресс-бар, resume при обрыве.
   3. Появление у партнёра: опрос list-метода по папке (или webhooks,
      если Я.Диск поддерживает wake-up через ntfy) → новый файл
      появляется в «Файлах» жены с уведомлением «Михаил загрузил:
      Договор.pdf». Офлайн — очередь, догружается при сети.
   4. Открытие: скачать в зашифрованный LRU-кэш (500 МБ), расшифровать,
      открыть в системном viewer/редакторе (PDF, DOCX, XLSX).
   5. Теги и поиск: «Налоги», «Путешествия», «Паспорта» (CRDT-метаданные),
      поиск по зашифрованным именам через локальный индекс (zero-knowledge).
   6. Приватные файлы: Private Box — отдельный пароль, байты хранятся
      локально зашифрованно, партнёр не видит.
   7. Наименование вкладки: в UI — «Файлы» (в коде остаётся docs).

   Ограничения/решения, зафиксировать в PLAN.md 5.4: актуальные лимиты
   API Я.Диска (размер файла, частота запросов), polling по updated_at,
   модель общей папки (общий аккаунт vs общий диск-попапка).


 ЧТО ЕЩЁ НАДО СДЕЛАТЬ
--------------------------------------------------------------------------------
 А) СОБРАТЬ И ПРОВЕРИТЬ (ближайший, главный шаг)
    1. pub get (core + ms_app) — уже валидные pubspec, нужно просто скачать
       зависимости (нужен интернет: pub.dev / dl.google.com).
    2. flutter analyze + flutter test (ms_app) + dart test (core) — зелёные.
    3. flutter build apk — получить первый настоящий APK.
    4. (опц.) headless-эмулятор (KVM) — запустить APK без телефона.
    → Всё это делает fetch_all.sh. ПРЯМО СЕЙЧАС на этой машине сеть ограничена
      (VPN): pub.dev и dl.google.com не доступны, Gradle-хост даётся. Сеть
      понадобится на шагах 1 и 3.

 Б) ПОДКЛЮЧИТЬ В ЯДРО (то, что есть в core, но ещё не «проведено» в UI)
    5. Реальная синхронизация L1/L2/L3: сейчас domain_store — чисто local
       (нет транспорта). Нужно провести транспорт (L1 локальная, L2/L3 сеть)
       между двумя устройствами + крипто-обёртку записи.
    6. E2E-шифрование в хранилище: crypto/ есть, но domain_store пишет JSON в
       открытом виде. Провести шифр-обёртку (server blind).
    7. Вкладка «Файлы» на Яндекс.Диске (ваше явное требование — см.
       отдельную секцию выше): OAuth, загрузка/скан, появление у
       партнёра, viewer, теги, Private Box. Ядро-клиент уже готов.
    8. Карты лояльности: сгенерировать реальный штрихкод/QR (qr_code /
       zxing) и сканер (mobile_scanner / ML Kit) на экране «Карты».
    9. Напоминания календаря: notifications.dart есть — привязать к событиям
       (точные алармы через setExactAlarm, DND-учёт).

 В) МОБИЛЬНЫЕ ДЕТАЛИ
    10. Android-разрешения в AndroidManifest (exact-alarm, камера для сканера,
        biometric) — проверить, что всё запрашивается.
    11. Иконка приложения (ic_launcher) — сейчас дефолтная; подставить нашу

    12. (опц.) виджет на домашний экран «ближайшее событие».

    13. ios/ скелет (flutter create --platforms=ios). Сборка IPA требует Mac

 Д) КАЧЕСТВО
    14. Расширить тесты: конфликт синхронизации (одновременное редактирование),

    6) → iOS (п. 13)


 КАК СОБРАТЬ / ПРОВЕРИТЬ
--------------------------------------------------------------------------------
 На машине с обычным интернетом (НЕ на VPN, который резит pub.dev):

   bash fetch_all.sh                 # лёгкий: Flutter + pub + тесты (headless)
   WITH_ANDROID=1 bash fetch_all.sh  # полный: + JDK17 + Android SDK + debug-APK
                                     #   + headless-эмулятор (нужен KVM)

 Результат:
   dist/ms_app_debug.apk         — готовый APK
   dist/ms_reports/*.txt         — отчёты (dart test / analyze / build / sdk)
   dist/ms_deps_bundle.tar.gz    — бандл (pub-кэш + отчёты [+SDK]) для переноса

 Примечание по этой машине: root/sudo недоступен, /dev/kvm требует группу kvm
 (мы вне её). Для сборки APK root не нужен (Gradle работает в user-space,
 нужен лишь JDK 17 — его скрипт должен ставить в ~/jdk без sudo). Для
 headless-эмулятора нужен KVM — без него эмулятор не запустится, но APK
 всё равно соберётся.
