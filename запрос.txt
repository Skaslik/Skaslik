ЧТО ЭТО
--------------------------------------------------------------------------------
Это форк приложения you&me — «общий дом для двоих» в виде мобильного
приложения. you&me — приложение для пары (календарь на двоих, списки,
напоминания, общий бюджет), мы делаем то же самое, но:

  • только для нас двоих (не масс-маркет): нет рекламы, монетизации,
    аналитики, аккаунтов, email-регистраций. Есть только качество и
    надёжность.
  • local-first + zero-knowledge: данные живут на наших телефонах, интернет
    нужен только чтобы два телефона синхронизировались. Ни один сервер
    (в т.ч. Яндекс.Диск) не видит содержимое — по транспорту ходит только
    шифртекст.
  • Android в первую очередь, iOS потом (один код Flutter → две сборки;
    APK на iPhone не ставится — нужен отдельный IPA, собирается с того же
    исходника на Mac).

ВАЖНО: это «живой» проект. Если есть идея, что добавить — это только
приветствуется. Ниже в разделе «ИДЕИ» уже набросано что можно, но любой
другой здравый пожелательный модуль в духе you&me / «общий быт пары» —
добавляем. Главное, чтобы он не ломал инварианты (см. ниже).

ИНВАРИАНТЫ (не обсуждаются)
--------------------------------------------------------------------------------
  I1  Никакого собственного сервера. Транзит синка = P2P (BLE/WebRTC) +
      зашифрованные блобы на Яндекс.Диске как «глупый транспорт».
  I2  Zero-knowledge: ни Яндекс, ни rелей не видят контент. Ключи — только
      на наших устройствах (+ бумажная seed-фраза дома).
  I3  Offline-first: всё работает без сети, синк фоновый и идемпотентный.
  I4  Быстрый старт: данные всегда локальные, UI отвечает мгновенно.
  I5  Безопасность из коробки: биометрия/PIN-гейт, фейк-режим (тройное
      тап по монограмме → калькулятор), zero-knowledge бэкап.
  I6  Никакого ML/LLM. Только детерминированные алгоритмы (сканер
      штрихкодов/QR, расчётные формулы, геометрия выравнивания скана).
  I7  Без монетизации/рекламы/трекинга/аккаунтов.
  I8  Конфликтостойкость по построению (CRDT): ни одна запись не теряется
      из-за одновременного редактирования / рассинхрона / перезагрузки.
  I9  Каждая «delight»-фича должна иметь смысл («я рядом, я помню»),
      а не быть игрушкой.

  │   L1 BLE / L2 WebRTC  ⏳      │                │                              │
  └──────────────────────────────┘                └──────────────────────────────┘
              │  (зашифрованные блобы, zero-knowledge)
              ▼
   Яндекс.Диск  /МС/<familyId>/  — только шифртекст (кто-то увидит —
   бессмысленные байты; AAD-тег домена не даёт подменить конверт другого
   домена)

Ключевые решения:
  • Pairing (один раз): каждое устройство генерирует X25519-ключ. Пара
    завершается обменом публичных ключей (вручную/QR) + общим секретом S
    (4 слова). Из пары выводится master-ключ (HKDF) → per-domain ключи.
  • Каждый домен синхронизируется отдельно: свой зашифрованный снапшот
    (op-log) кладётся в свой файл. Конверт = XChaCha20-Poly1305 + AAD,
    зависящий от имени домена → конверт «banks» нельзя открыть как
    «calendar».
  • CRDT: каждое событие/запись — op {seq, time(Lamport), deviceId,
    entityId, field, value}. Мерж = last-writer-per-field по (time,
    deviceId). Удаление = tombstone. Сходимость — коммутативна, проверена
    тестами.
  • Device ID = детерминированная хеш-функция от публичного ключа: один
    ключ → один id (важно для LWW-тайбрейка и «кто автор»).

 ИДЕИ, ЧТО МОЖНО ДОБАВИТЬ (только приветствуется)

Все идеи ниже — в духе you&me / «общий быт пары», НЕ ломают инварианты
(без ML, без сервера, offline-first, zero-knowledge). Пошлифовано под
нашу пару. Разбита по effort: «дёшево» = 1 поле в существующем CRDT,
«средне» = новый домен, «крупно» = домен + UI + синк.

[Дёшево — быстро, высокая ценность для пары]
  • СОВМЕСТНЫЙ БЮДЖЕТ / расходы (дополнение к копилкам). Копилки =
    накопления на цель. А вот «кто сколько потратил на еду/ЖКХ/транспорт в
    месяце, кто кому должен» — отдельный домен spending: запись {кто, сумма,
    категория, дата, заметка}. Итог по человеку/месяцу, «расчёт». Вы уже
    просили «вклад каждого» — это его естественное расширение. [средне]
  • СПИСКИ ПОКУПОК / дел (расширение notes). Общий чек-лист «Список на
    дачу»: у каждого свои галки (CRDT), можно назначить «кто несёт хлеб».
    Уже есть notes-чеклист — доводим до «список покупок с разделением». [дёшево]
  • ДОЛЖНОСТИ / чей день (chores rotation). «Сегодня за стирку отвечает
    Михаил». Недельная ротация + streak. Детерминированно, I6 ок. [дёшево]
  • СОВМЕСТНЫЕ ПОДПИСКИ (subscriptions). Рекуррентные платежи: интернет,
    стриминг, страховка — «обновление 15-го, 499 ₽», разбивка пополам,
    напоминание за день. [дёшево]
  • БЛИЖАЙШИЕ ГОДОВЩИНЫ / ДР на home. Уже есть anniversary auto-detect в
    ядре — остаётся вывести на home панель «в ближайшие 30 дней». [дёшево]
  • ПАМЯТКИ ДОКУМЕНТОВ (сроки). У документов (вкладка Файлы) — срок
    годности/действительности (паспорт, страховка, права) → напоминание
    «через 60 дней истекает». [дёшево]

[Средне — новый домен, заметная ценность]
  • ОБЩИЙ ВИШЛИСТ / подарки. «Идеи подарков» + кто дарит + бюджет +
    «уже куплено». Особенно к ДР/свадьбе. [средне]
  • ОБЩИЕ ФОТО-АЛЬБОМЫ (по событию). «Дача, июль 2026» — альбом к
    событию/дате, E2E-фото, общий просмотр. (Медиа-кэш уже заложен в
    модели.) [средне]
  • ГОЛОСОВЫЕ ЗАМЕТКИ. Запись → Opus/OGG → шифрованный blob → синк.
    Без транскрипции (I6). «Купи хлеб» голосом. [средне]
  • МЕДИКАМЕТЫ / ЗДОРОВЬЕ. Рекуррентные напоминания: «витамины, утро»,
    «УЗИ, 14-го» (уже есть в календаре, доводим до «здоровье»). [дёшево]
  • АВТО / ДОМ (обслуживание). Замена масла каждые X км/мес, ТО, страховка,
    фильтры. Reminders по дате/пробегу. [дёшево]
  • ГОРЯЩИЕ ДАТЫ / «не забудь» (quick capture). Один тап — «не забыть
    купить X» → в общий список + push. [дёшево]

[Крупно — только если захотим]
  • ОБЩИЙ БУФЕР ОБМЕНА (Universal Clipboard for two). Скопировал ссылку →
    на втором телефоне «Принять?» → в буфер/сообщение. (Уже в PLAN как
    clips-домен, не реализовано.) [крупно]
  • «МАЯЧОК» / ритуалы (delight). Уж есть ритуал-точки и пульс в room —
    доводим до «я думал о тебе» с анимацией. [дёшево, уже заложено]
  • КАРТА «ПАМЯТЬ МЕСТ» (Places). Отметки на карте (где были вместе),
    радиус, фото, заметка. [крупно]
  • ОБЩИЙ ДОГОВОР-ПРИГОВОР (юридический текст + подпись пальцем).
    «Мы скидываемся по 10к до 1 мая» — svg-подпись, хранится в docs.
    (Уже есть контракт-концепция в PLAN.) [средне]

[Сознательно НЕ делаем (I6/I7)]
  • ML-распознавание чеков/настроений/«умные» подсказки — нет.
  • Подключение банков (OpenAPI Тинькофф/Сбер) — нет (по решению: ручной

  • Реклама/аналитика/аккаунты — нет.
