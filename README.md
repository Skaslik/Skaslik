# МС — семейное приложение пары

Единое приложение для пары (Михаил & София): общий календарь, копилки, документы,
карты лояльности, сообщения, заметки и «Комната» — живой общий фид.
Local-first, E2E-шифрование, синхронизация между устройствами.

> Личное приложение для двоих. Нет монетизации, нет рекламы, нет аналитики.

## Структура

```
core/      Ядро: чистый Dart (без Flutter). Крипто, pairing, seed-phrase,
           CRDT-реплика (LWW + гибридные часы), доменные модули, sync engine,
           Yandex.Disk client. Покрывается unit-тестами.
ms_app/    Flutter-приложение (Android + iOS из одного кода).
           Дизайн-система, экраны, local-first store поверх core, блокировка.
docs/      tech-spike.md — исследование и зафиксированные решения.
```

## Быстрый старт

```bash
# 1) Ядро: проверить крипто/CRDT/домен
cd core
dart pub get
dart test

# 2) Приложение: запустить
cd ../ms_app
flutter pub get
flutter run            # на подключённом устройстве (Android)
# или
flutter run -d iphone  # iPhone
```

## Сборка на машине без интернета к pub.dev

Скрипт `fetch_all.sh` (в корне) на машине со стабильным интернетом Linux x64:

```bash
mkdir ~/work && cd ~/work
unzip /путь/к/ms_project.zip
bash fetch_all.sh
```

В `~/work/dist/` появляются: `ms_pub_cache.tar.gz` (pub-зависимости для
offline-сборки), `ms_reports/` (dart test, analyze, flutter test, pubspec.lock),
`ms_app_debug.apk` (отдаётся на телефон без USB). SDK ставится в `~/work/flutter`.

## Архитектура

**Local-first.** Источник истины — на устройстве: CRDT-реплика (LWW-регистры +
гибридные часы + tombstones). Сходимость гарантирована: любое множество
изменений, применённое в любом порядке, даёт идентичное состояние. Проверено
тестами (5 устройств, 500 ops, property-based).

**Zero-knowledge.** По транспорту ходят только зашифрованные blob'ы. Сервер
(Яндекс.Диск как S3) не видит содержимое.

**Синхронизация (приоритет):** L1 BLE → L2 WebRTC → L3 Яндекс.Диск.
Оркестратор пробует контуры по очереди; при недоступных — offline-ожидание.

**L3 (Яндекс.Диск) — реализовано:** `YandexAuth` (OAuth PKCE, loopback-redirect
RFC 8252, токены в SecureVault) → `YandexBlobStore` (chunked upload, ensureDir)
→ `DiskSync` (zero-knowledge конверт: XChaCha20-Poly1305 + AAD по домену) →
`SyncService` (публичует свой снапшот, скачивает и применяет файл партнёра;
CRDT-merge). Домены изолированы AAD-тегами; файл другого домена не
расшифровывается.

## Модули

| Модуль        | Статус                                   |
|---------------|------------------------------------------|
| Календарь     | Список + добавление, recurrence, годовщины, напоминания |
| Комната       | Живой фид: пульс дня, ритуалы 💗, капсулы времени, лента |
| Копилки       | Цели, вклады, штрафы, прогресс, прогноз   |
| Карты         | Штрихкоды (EAN-13 с контрольной), категории, избранное |
| Документы     | Реестр (S4: загрузка в S3/Я.Диск, сканер, теги, приватные папки) |
| Сообщения     | Текст/пинги, burn-режимы (TTL/onView), scheduled delivery |
| Заметки       | Общие, теги, закрем                       |
| Настройки     | Статус семьи, данные, безопасность, сброс |

## Безопасность

- **Блокировка приложения** — Face ID / Touch ID / PIN (`local_auth`).
- **Fake mode** — тройное нажатие на монограмму → фейковый калькулятор
  (никаких данных семьи). Настоящий доступ — только по биометрии.
- **E2E** — контент шифруется на устройстве; сервер не видит содержимое.
- **152-ФЗ** — данные на инфраструктуре в РФ; согласие на онбординге.
- **Двухфакторное удаление** — согласие обоих или аварийный код.
