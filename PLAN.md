## 1. Продукт: концепция и инварианты

### 1.1. Суть
Приложение «МС» (Михаил & София, семья Афана́севых) — приватная digital-среду для одной
пары: общий календарь, общие документы, копилки, карты лояльности, общие сообщения и
заметки. Это **внутренний продукт для 2 пользователей**, а не масс-маркет.

### 1.2. [ИНВARIANT] Ключевые инварианты (non-negotiable)

| # | Инвариант | Обоснование |
|---|-----------|-------------|
| I1 | **Никакого собственного сервера.** Данные живут на устройствах. Транзит синхронизации — P2P (локальная сеть/BLE/WebRTC) + зашифрованные blobs на Яндекс.Диске как «глупый транспорт» + ntfy как push-релей для «разбуди меня синхронизироваться». | Нет точки утечки, нет оплаты, полная автономность |
| I2 | **Zero-Knowledge по отношению ко всем посредникам.** На Яндекс.Диске и в ntfy лежит только шифртекст / служебные сигналы. Ключи никуда не уходят, кроме устройств пары (и бумажной seed-фразы дома). | Даже компрометация Я.Диска ничего не раскрывает |
| I3 | **Offline-first.** Каждый модуль полностью функционален без сети. Синхронизация — фоновая, идиотентичная, с очередями. | Самолёт, метро, дача |
| I4 | **Критично-быстрый старт.** Холодный старт < 1.5 c (Android mid-range), первое осмысленное содержимое < 300 мс (данные всегда локальные). | Доверие к «своему» приложению |
| I5 | **Безопасность «из коробки».** Biometric-гейт, фейк-режим, двухфакторное удаление, zero-knowledge backup — это не опции, а часть MVP. | Интимность пары |
| I6 | **Никакого ML/LLM.** Ни LLM, ни on-device ML-модели, ни «интеллектуальные» подсказки, ни OCR чеков/карт. Разрешены ТОЛЬКО детерминированные алгоритмы: сканер штрихкодов/QR (обязателен для карт лояльности), геометрическое выравнивание сканов документов, расчётные формулы. | Пользовательское решение: ML усложняет без пользы |
| I7 | **Никакой монетизации, рекламы, аналитики-трекинга, email-регистрации, аккаунтов.** Внутренний продукт. | Смысл продукта |
| I8 | **Конфликтостойкость по построению (CRDT).** Ни одна запись пары не может быть потеряна из-за одновременного редактирования, рассинхрона или перезагрузки. Данные — святое. | Потеря общего календаря/истории = критический инцидент |
| I9 | **Каждая «delight»-фича должна иметь смысловую нагрузку** («я помню, я рядом, я забочусь»), а не быть игрушкой. | Тон продукта |

### 1.3. Целевое ощущение
«Цифровой общий дневник/дом». Мягкий, тёплый, минималистичный. Никакой корпоративной
жёсткости. Пустые состояния — тёплые, с юмором (короткие фразы-подписи, без карикатур).

### 2.1. Общая схема

### 2.2. Транспорт: три контура

| Контур | Когда | Что переносит | Задержка |
|--------|-------|---------------|----------|
| **L1 — BLE** | В одном телефоне-радиусе (~10 м), всегда | Discovery-объявления, small deltas (CRDT changes ≤ 200 КБ) | < 1 с |
| **L2 — WebRTC data channel** | Та же сеть/интернет, крупные объёмы | Media-файлы, большие deltas, кэш | ~1–3 с |
| **L3 — Яндекс.Диск bus** | Любое расстояние, офлайн-дополнение | Шифртекст-блобы синка (по 1–100 КБ), файлы документов | 1–5 мин (поллинг) |

Правила:
- Приоритет L1 → L2 → L3. Sync Engine сам выбирает контур; для пользователя это
  одна кнопка «Синхронизировать» + индикатор статуса.
- Каждый blob: `[domain][seq][sender_id][ciphertext][sha256]`. Повторная отправка
  идемпотентна (dedup по seq+sender).
- Лимиты Я.Диска (ориентир, верифицировать в S0: ~50 req/s, троттлинг на частые
  операции) для нас не критичны: синхроблобы — единицы запросов в минуту.

### 2.3. Честные ограничения (закрепить в UX)
- Без интернета-релея нет мгновенного push «жена добавила событие» на расстоянии.
  ntfy закрывает это с задержкой ~1–5 с (онлайн) и гарантирует доставку при любом
  раскладе (L3). UX-формулировка: «синхронизация — почти мгновенная рядом,
  минутная на расстоянии». Это НЕ баг, а свойство zero-server архитектуры.
- iOS ограничивает фоновые WebRTC-сокеты (~30 с без activity) → фоновый синк на iOS
  opportunistic; гарантию доставки даёт L3. На Android foreground-service синка
  работает стабильнее.

### 2.4. Crypto-схема

1. **Pairing (один раз):**
   - Устройство A генерирует: curve25519 keypair (транспортный), 12 слов seed-фразы
     из списка 2048 слов (выбираем список заранее, хранится офлайн).
   - Пароль-секрет пары **S**: пользователь A диктует/вводит на обоих устройствах
     (генерируется в приложении: 4 слова + показывается один раз).
   - Обмен транспортными ключами: по QR (L1/BLE при встрече) — forward secrecy на
     транспортном уровне (X3DH-lite: ephemeral + long-term keys).
2. **Derivation:** `Argon2id(S + pairing_salt)` → master key → HKDF → per-domain keys:
   `k_calendar, k_docs, k_banks, k_messages, k_clipboard, k_notes`.
3. **CRDT-документы**: каждый domain — отдельный Automerge-док; синк шлёт зашифрованные
   changes (XChaCha20-Poly1305, nonce = domain_id || seq || rand96).
4. **Файлы**: AES-256-GCM, ключ = HKDF(k_docs, file_id). Медиа-кэш на диске зашифрован.
5. **Private Box**: отдельный пароль **P_box** (не выводится из S), Argon2id →
   box-key. Данные box не читаются без P_box, ключ box не хранится в общих документах.
6. **Recovery:** seed-фраза (бумажный лист дома) + S позволяют восстановить всё.
   Партнёр может восстановить данные второго (общий S) — это и есть «zero-knowledge
   бэкап на двоих». Плюс: еженедельный локальный encrypted snapshot-экспорт (PDF/JSON
   шифртекст) с отправкой на WebDAV/email — опция.

### 2.5. Data Model (CRDT-документы, логические сущности)

```
Family
  id (pairing_id), name, created_at
  members[2]: { user_id, name, avatar_ref, color, tz, created_at }

Event (calendar)
  id, title, description, color (owner|shared), all_day
  start_ts, end_ts, location {name, lat, lng, geocode_ref}, tz
  remind_rules: [{offset_min}]  // локальные notification-правила
  invite_status: created/accepted/declined  // для событий-приглашений
  recurring: none|daily|weekly|monthly|yearly  // детерминированное правило
  anniversary: bool  // авто-пометка годовщин (дeterministic: date match)
  owner_id, edited_by, vclock

PiggyBank
  id, goal_name, icon_ref, target_amount, target_date, currency
  contributions: [{id, by_user_id, amount, at, note}]
  fines: [{id, by_user_id, to_user_id, amount, at, reason}]  // «штрафы»
  history (append-only)

LoyaltyCard
  id, merchant_name, category (супермаркеты|аптеки|заправки|кафе|другое)
  barcode { type: QR|EAN13|CODE128|PDF417, value }
  card_number?, note, favorite: bool, last_used_at, owner_id

Note (общие заметки/списки — You&Me-core)
  id, title, body (CRDT-текст), checklist [{id, text, done, by}],
  tags[], pin, owner_id

Message (общие сообщения)
  id, from_user_id, kind: text|voice|photo|ping
  payload_ref (local/blob), burn: none|24h|on_view, view_state
  scheduled_for_ts?  // «открыть в X» (async closeness)

Clip (общий буфер обмена)
  id, from_user_id, kind: text|link, ciphertext, expires_at (72h), accepted: bool

Ritual (микро-ритуалы, v1.1)
  id, from_user_id, kind: dot|beacon, at

Capsule (капсула времени, v1.1)
  id, title, media_refs[], letter (CRDT-текст), seal_date,
  opened: {at, by_both: bool}

Pulse (пульс дня, v1.1)
  id, user_id, day, value (энергия|усталость|обнимашки), note?

Places (память мест, v2)
  id, name, lat, lng, radius, media_refs[], note
```

Файлы документов хранятся **не в CRDT**: метаданные (FileMeta) — в CRDT
(название, теги, размер, sha256, storage_ref = disk_path|local_blob), байты —
Яндекс.Диск (общие) / локально зашифрованно (private box, медиа сообщений).

## 5. Модули (спецификации)

Формат: Суть → User Stories → UX → Техническое → Критерии приёмки.

### 5.1. Onboarding & Pairing
**Суть.** Два устройства, ноль email, ноль аккаунтов.

**Stories.**
- US-1: Михаил открывает новое приложение → «Создать семью» → генерация S (4 слова)
  и seed (12 слов) → печатает лист.
- US-2: София вводит S (по QR от Михаила — слова передаются QR-ом, не голосом,
  чтобы не ошибиться) → devices pairing → семья готова.
- US-3: Потеряно устройство → новое устройство восстанавливается по seed+S.

**Техническое.**
- Экраны: Welcome → Create/Join → Pairing (QR/ввод) → Профиль (имя, цвет, аватар из
  галереи) → Biometric setup → Done.
- QR содержит: pairing_id + transport pubkey + S-подсказку (S передаётся QR-ом,
  сканируется вторым устройством — zero-knowledge по Wi-Fi).
- После pairing — обязательная настройка biometric-гейта (можно отложить 1 день).

**Приёмка.**
- [ ] Полный pairing 2 устройств ≤ 3 минут, без интернета.
- [ ] Seed+S → восстановление данных на 3-м устройстве (тест вручную).
- [ ] При повторном вводе S на 3-е устройство — отказ (максимум 2 устройства;
      снятие устройства — «dissociate» с подтверждением обоих).

### 5.2. Home (главный экран)
**Суть.** «Общий дом» в компактном исполнении: дашборд-карточки, а не список чатов.
[ОТКРЫТО-1]: дашборд (рекомендация, MVP) vs буквальная «комната» (метафора, v2+).

**Композиция (сверху вниз):**
1. Строка статуса: монограмма, имя дня, статус синхронизации (иконка: ● онлайн / ◐
   очередь / ○ офлайн), аватары пары.
2. «Сегодня»: ближайшие 3 события (EventCard mini), тап → календарь.
3. «Копилки»: топ-2 активных (кольцо % + последний взнос).
4. «Свежее»: последние сообщения/заметки (1–2 превью), новые документы.
5. Быстрые действия ( FAB-меню): + событие, + в копилку, скан карты, фото в документы.
6. Индикатор «маячок» (v1.1): если партнёр прислал ритуал-точку — на home
   появляется анимированная точка.

**Приёмка.**
- [ ] Холодный старт → home с реальными данными < 1.5 с.
- [ ] Все секции тачабельны и ведут в модули.
- [ ] Пустые состояния: тёплые тексты, без «нет данных».

### 5.3. Календарь (core)
**Stories.**
- US: «Добавить: УЗИ, 14-го, 10:00, клиника X» → жена видит в своём календаре,
  у обоих локальные напоминания.
- US: «Событие "Анна-Мария, 14 лет"» → recurring yearly → 14-го каждого года
  напоминание + годовщина на home.
- US: Жена изменила время → у мужа обновилось, история изменений видна (кто/когда).
- US: «Пригласить» — событие-приглашение: жена может принять/отклонить.

**UX.**
- Виды: Месяц (сетка, точки-цвета), Неделя (таймлайн-бары), Список (дни-группы).
- Цвет: события создателя — цвет создателя; событие, которое отредактировал второй
  (или помечено общим) — градиент. Легенда цветов.
- Карточка события: заголовок, время (локальное TZ каждого), место (тап → Yandex/Google
  Maps deeplink с маршрутом), описание, чек-лист (для событий-списков покупок),
  комментарии (CRDT-текст), «изменено: Софией, 2 мин назад».
- Recurrence: none/daily/weekly/monthly/yearly + исключение конкретного вхождения.
- Anniversary-автопометка: при создании события с датой без времени — вопрос
  «повторять ежегодно?» (опционально, по умолчанию off).

**Техническое.**
- Все события в CRDT-доке `calendar`. Редактирование = merge по полям;
  `vclock` + `edited_by/at` для отображения. Конфликты «по построению» отсутствуют
  (CRDT); семантика: поле выигрывает у того, кто позже его трогал (last-writer-per-field
  из CRDT — это естественное поведение Automerge для scalar-полей).
- Напоминания: `flutter_local_notifications`, планируются при каждом merge
  (re-schedule delta): правило = `start - offset`. Правила: [за 1 день, за 1 час,
  за 15 мин] — настраиваются в событии.
- DST/переезды: храним `ts` + TZ; при смене TZ устройства пересчитываем отображение,
  «якорим» события к моменту создания (timezone of creation).
- Экспорт/импорт `.ics` (личное резервирование, детерминированный формат).

**Приёмка.**
- [ ] 2 устройства, 50 событий, одновременное редактирование разных полей → merge без потерь.
- [ ] Напоминания сработали в офлайне (авиа-режим) по локальному расписанию.
- [ ] Recurring yearly: событие 2026-10-14 → напоминание 2027-10-14 (тест дат).
- [ ] Вишукосный 2028, переход часовых поясов (тестовые TZ: Europe/Moscow, Asia/Almaty, America/New_York).
- [ ] Deeplink на карту с геоточкой открывает маршрутизацию.
- [ ] Импорт 500-событийного ICS < 5 с.

### 5.4. Хранилище (вкладка «Файлы» / Документы)
**Суть.** Гибридное: метаданные в CRDT, байты — Яндекс.Диск (общие) / локально
(private box). Приложение — «живая папка»: открытие в системном viewer/редакторе.

**[ТРЕБОВАНИЕ ПАРЫ, 02.10.2026]** Вкладка «Файлы» — общие документы:
я загружаю документ — и он всегда в доступе у обоих, с любого устройства.
Хранение байтов — Яндекс.Диск (общая папка пары), приложение — «живая
папка». В UI раздел называется «Файлы» (в коде: docs). Это приоритет №3
roadmap (после APK и иконки/разрешений).

**[РЕШЕНО, 02.10.2026]** Модель общей папки: **один общий аккаунт Яндекса** на
пару. Оба телефона авторизуются в него (OAuth PKCE). Файлы в
`/Документы/` видны обоим сразу. L3-поллинг по `updated_at` этой папки.

**Stories.**
- US: «Сфотографировать чек/паспорт» → сканер: серия кадров, авто-выравнивание,
  сохранение в PDF (общие) или в Private Box.
- US: «Загрузить PDF договора» → файл уходит на Я.Диск в `/Семья/Документы/`,
  жена видит его в приложении через 1–5 мин (L3) или мгновенно (L1/L2).
- US: «Открыть в Word/Google Docs» → системный viewer/editor.
- US: Теги: «Налоги», «Путешествия», «Паспорта» — фильтры.

**UX.**
- Структура: «Общие» (сетка/список: документы, сканы, медиа), «Папки» (пользовательские),
  «Private Box» (отдельный пароль, иконка-замок, содержимое не видно второму).
- Карточка файла: превью (PDF — первая стр., фото — кадр), имя, размер, тег,
  «кто загрузил, когда».
- Поиск: по имени + тегам (без фултекста по содержимому — I6).
- Private Box: при первом открытии — пароль P_box; внутри — только шифртекст,
  без превью (privacy), превью рендерится локально после unlock.

**Техническое.**
- **Yandex.Disk клиент (собственный, тонкий):**
  - OAuth2: authorization-code + PKCE (native webview → callback), scope
    `disk_api:disk.info, disk_api:disk.content.read, disk_api:disk.content.write`.
  - Refresh-token в secure storage; авто-renew; обработка 401/429 (backoff).
  - Диск-структура: `/Семья/<pairing_id>/Документы/`, `/Семья/<pairing_id>/Синк/<domain>/`.
  - Загрузка: multipart/chunked для > 50 МБ; прогресс-бар; resumable.
  - **Верифицировать в S0:** актуальные лимиты API, возможность polling по
    `updated_at` папки (метод `list` + фильтр), webhooks (если есть — использовать
    для wake-up вместо поллинга).
- **Локальный кэш**: LRU, 500 МБ, зашифрован (k_docs), превью-thumbnails.
- **Сканер**: камера → серия → (опционально) perspective warp (opencv_dart) →
  PDF (pdfrw/image-to-pdf) → загрузка. Ручной crop обязателен (fallback без OpenCV).
- **FileMeta (CRDT):** {id, name, size, sha256, mime, tags, storage: disk_path|box|msg,
  uploaded_by, at}. Байты-в-CRDT запрещены.
- Медиа (фото в сообщениях): байты в зашифрованном blob на Я.Диске + локальный кэш.

**Приёмка.**
- [ ] Загрузка 200 МБ видео → прогресс, resumable после обрыва сети.
- [ ] File на диске виден в приложении после синка (L3) < 5 мин.
- [ ] Private Box: без P_box — нулевой доступ (тест: снять приложение, перебрать файлы БД → только шифртекст).
- [ ] Скан 5 страниц паспорта → корректный PDF, выравнивание ≤ 2° перекоса (тестовые фото).
- [ ] «Открыть в системном» — deeplink работает (PDF, JPG, DOCX-внешний).
- [ ] Отключение аккаунта Я.Диска: приложение не падает, документы в кэше доступны,
      новые загрузки — в локальную очередь (L1/L2 delivery).

### 5.5. Копилки
**Суть.** Цели с визуальным прогрессом, вклады каждого, штрафы, предсказание.

**Stories.**
- US: «На отпуск, 150 000 ₽, к 1 июня» → кольцо, история.

  получателя, сумма, причина) — с юмором (эмодзи/фразы-пресеты).
- US: «Когда достигнем цели при таких взносах?» → детерминированный расчёт:
  средняя скорость взносов (последние 30 дней) → прогнозная дата + «нужно по X/мес
  до 1 июня» (reverse-расчёт).

**UX.**
- Карточка: название, иконка (набор из ~12: машина, отпуск, ремонт, техника,
  ресторан, здоровье, дом, другое), кольцо прогресса (цвет shared-градиента),
  сумма/цель, «до цели: X ₽», предикционная дата.
- Экран: вкладки «Цель» (кольцо, прогноз, история append-only с аватарами)
  «Пополнить» (сумма, быстрые: 500/1000/5000, заметка, «штраф»-режим).
- Завершённые → архив с итоговой статистикой (сколько каждый внёс, %).
- Округление (round-up): НЕ автоматически (без ML и без банковского API) —
  «ручной» quick-action: «докинуть до 1000» после записи взноса.

**Техническое.**
- CRDT-док `banks`, append-only history (никаких «переписываний истории» —
  только add; «отмена взноса» = компенсирующая запись с пометкой).
- Валюта: одна на семью (₽), поле `currency` на будущее.
- Прогноз: простая арифметика (без ML): linear extrapolation по скользящему среднему.

**Приёмка.**
- [ ] Одновременные взносы с двух устройств → история полная, сумма = сумма взносов.
- [ ] Прогнозная дата пересчитывается при новом взносе.
- [ ] Архив: итог по каждому участнику точен (сумма history).
- [ ] Штраф отображается в истории с меткой «штраф» и причиной.

### 5.7. Сообщения и заметки (You&Me-core + burn)
**Суть.** Лёгкий общий канал (не Telegram, а «общая записка на холодильнике»):
текст, голос, фото, пинги. + общие заметки/списки дел.

**Stories.**
- US: «Купи хлеб» (текст) / голосовое 30 c (без транскрипции — I6) / фото рецепта.
- US: «Огонёк» на сообщении → сгорает через 24 ч или после просмотра (on_view);
  в истории — бледный след: «здесь было что-то тёплое».
- US: «Не открывать до вторника 08:00» → scheduled delivery (async closeness):
  конверт с датой; доставляется по расписанию локально у получателя.
- US: Пинг-«точка» (ритуал, v1.1) — тап по сердцу → у партнёра на home точка.
- US: Общие заметки: «Список на дачу» (чек-лист, у каждого галки свои), «Идеи
  подарков» (CRDT-текст, simultaneous editing).

**Техническое.**
- CRDT-док `messages` (append-only) + `notes` (CRDT-текст — concurrent editing).
- Голос: запись → OGG/Opus (локально) → шифрованный blob (L1/L2/L3).
- Burn: `burn: none|24h|on_view`; timer локальный у получателя; после сгорания —
  payload удалён с обоих устройств (Tombstone в CRDT: `burned_at`, метаданные
  остаются для «следа»).
- Scheduled: `scheduled_for_ts` — сообщение скрыто у получателя до срока;
  доставка гарантируется синком (не пушем): как только синк прошёл и срок наступил —
  показ + локальное уведомление.

**Приёмка.**
- [ ] Конкурентное редактирование заметки с двух устройств → merge текста без потерь.
- [ ] Burn on_view: открыл → у обоих payload исчез, «след» остался.
- [ ] Scheduled: создал в 22:00 с доставкой 08:00 → пришло ровно к сроку,
      уведомление локальное.
- [ ] Голосовое 2 мин → качество Opus, доставка офлайн-ок (L1 при встрече).

### 5.9. Безопасность и приватность (сводный модуль)
- **Biometric-гейт** (I5): при открытии + при входе в Private Box + (опция) при
  показе карты лояльности.
- **Fake Mode** (Panic): тройное тап-нажатие на монограмму → приложение
  «сворачивается с экраном блокировки»; при следующем открытии ввод
  **decoy-пароля** (отдельный) → открывается «калькулятор» (рабочий, с правдоподобной
  историей) — в нём нет НИЧЕГО. Настоящий интерфейс — только настоящий biometric/пароль.
  Decoy-vault: отдельное хранилище с фиктивными данными (опционально заполнить).
- **Двухфакторное удаление**: «Стереть всё» — только подтверждением обоих
  (подпись-фразой, которую оба вводят одновременно) или аварийным кодом из seed.
- **Zero-knowledge recovery**: seed-лист (12 слов + S) → восстановление на любом
  устройстве; «soft-рекавери» — второй партнёр восстанавливает данные первого
  (общий S, разные transport-ключи).
- **Аудит-лог (локальный)**: кто когда делал pairing/dissociate/восстановление/
  удаление (append-only, шифруется).
- **Утечки-чек (обязательный QA, секция 9)**: логи, crash reports, shared prefs,
  кэш — никакого plaintext S/P_box/данных.

**Приёмка.**
- [ ] Fake mode: decoy-пароль → калькулятор; настоящий биометр → реальное приложение;
      переключение мгновенно, без «мерцания» реальных данных.
- [ ] Forensic-тест: дамп памяти/файлов приложения — нет plaintext секрето
  и контента (чек скриптом + вручную).
- [ ] Dissociate устройства: после снятия — на старом устройстве данные
      перезаписаны (secure wipe локального хранилища).
- [ ] Восстановление по seed на 3-м устройстве — полный объём данных.

| Clip-приглашение | Система | «Михаил скопировал ссылку — принять?» |
| Документ загружен (L3-синк) | Документы | «Новый документ: Договор.pdf» |
| Сбой синка (длинная очередь) | Система | «Ожидает синка: 4 записи (нет сети)» |

Правила:
- `flutter_local_notifications`, отдельные Android-каналы (Calendar/Documents/
  Banks/Messages/System) — user может отключить по категориям.
- Напоминания планируются локально (survive офлайн/авиа).
- Группировка (notification groups) по модулям.
- «Не беспокоить» уважаем (no critical-priority abuse).
- Вибрации: деликатные (rhythms: 1 короткая для ритуала-точки, двойная для сообщения).

## 8. Офлайн-режим (cross-cutting)

- Все 6 CRDT-доков + файловый кэш работают офлайн.
- Очередь исходящих: append-only журнал изменений → синк при появлении контура.
- Статус-индикатор на home: `●` (свисинчено) / `◐` (N в очереди) / `○` (офлайн).
- Кнопка «Синхронизировать сейчас»: принудительная попытка L1→L2→L3.
- «Airplane test» (обязательный QA): полный рабочий день в офлайне → включить
  сеть → всё синхронизируется, конфликтов нет, ничего не потеряно.

## 12. Риски

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| flutter_webrtc/BLE неустойчивы в фоне (особенно iOS) | Средняя | L3 (Я.Диск bus) — гарантированный floor; P2P — оптимизация, не зависимость |
| Лимиты/изменения API Я.Диска | Низкая | Тонкий клиент, верификация в S0, деградация к L1/L2 |
| ntfy.sh недоступен/закрыт | Низкая | Self-host ntfy (docker, 5 строк) на домашнем сервере; без ntfy работает L3-поллинг |
| Automerge: размер доков (10k сообщений) | Средняя | Разделение по доменам уже есть; при 50 МБ+ — ротация (архив старых в blob) |
| APK-размер с OpenCV | Средняя | OpenCV — optional AAR / lazy-load; fallback без выравнивания |
| Дизайн «второго слоя» раздувает scope | Высокая | Строгая приоритизация (секция 6), delight — только после стабильного MVP |
