# МС — implementation spec for the new UI

This is the build spec for the agreed design. The look comes from `screenshots/`, `reference-web/` and `tokens.json`. Behaviour comes from this file and `reference-web/prototype/Main.dc.html`. The product rules come from `../../PLAN.md` and `../../запрос.txt`.

UI copy stays in **Russian** exactly as in the screenshots, and the app talks to the user as «ты».

---

## 0. What to read and in what order

1. `README.md` (this folder): a map of the files.
2. `brand-book.md`: colour, type, spacing, voice and icon rules (in Russian).
3. `screens.md`, `room.md`, `decisions.md`: navigation, the home scene, and the open choices.
4. Screenshots (`screenshots/*.png`). Each screen exists in `evening` (dark, default) and `day`. The mock-ups draw a fake status bar and a phone frame; **do not implement either**. Use the real system status bar, edge-to-edge.
5. `reference-web/previews/*.html`: the exact paddings, radii and font sizes as CSS. Open them in a browser; they work offline. `reference-web/bundle.css` is the CSS for all components.
6. `reference-web/prototype/Main.dc.html`: the clickable prototype's logic. Its `renderVals()` holds every interaction (candle, PIN, fake calculator, add event, check list, +1 000 ₽, theme switch). Read it as a behaviour spec; it does not run outside Claude's canvas.

## Phase 1 — Foundation: tokens, theme, base widgets

- Copy `flutter/ms_tokens.dart` to `ms_app/lib/design_system/ms_tokens.dart`. It is generated by `tools/gen_dart.py`; regenerate it after any change to `tokens.json`, never edit it by hand.
- Build `ThemeData` for each palette in `ms_theme.dart`. Keep the class name `MsTheme` and give it `evening()` and `day()`:
  - `scaffoldBackgroundColor: ground`, `brightness` dark/light.
  - `ColorScheme`: primary = flame, onPrimary = onFlame, surface = surface, onSurface = ink, error = danger, outline = line.
  - Register `extensions: [MsThemeExtension(palette)]`. Widgets read colours through `context.ms`.
  - `fontFamily: 'Onest'`; `textTheme` taken from `MsText`; set `SystemUiOverlayStyle` per theme.
- Theme mode: a `ThemeController` (Riverpod) with `auto | evening | day`, persisted.
  - In `auto`, «День» runs from sunrise to sunset for the configured city (default Москва 55.7558, 37.6173), using the deterministic NOAA sunrise equation — allowed by I6. Fall back to 07:00–19:00.
  - The manual switch lives in «Мы → Тема». The prototype shows Вечер/День; add «Авто» as the first segment.
- Base widgets in `lib/design_system/widgets/`, each with a widget test. Use the matching `screenshots/<name>_*.png` and `components/<Name>.md`:
  - `MsEyebrow` (mono 11, upper-case, +0.08em, inkMuted)
  - `MsMeta`
  - `MsCard` (surface, radius 20, padding 16/20)
  - `MsRowCard` (surface, radius 14, padding 12/14, min-height 56)
  - `MsDateBlock` (48 wide, number + sub-label)
  - `MsAuthorBar` (3 px; michael / sofia / both = two halves)
  - `MsAuthorDot` (8 px)
  - `MsChip` (32 px pill; selected = ink fill with ground text; person chip = *-soft fill + coloured border)
  - `MsSegmented` (track = surface; selected = surfaceRaised + 1 px line)
  - `MsButton` (primary flame/onFlame, secondary, ghost/link, danger, small pill; 48 high, radius 14)
  - `MsSyncStatus` (● ◐ ○ ✕ + word)
  - `MsProgressSplit` (segments michael / sofia / warn with 2 px gaps)
  - `MsSheet` (bottom sheet: ground, radius 20 at the top, grab handle 36×4, scrim)
  - `MsToast` (ink background, ground text, radius 14, sits above the tab bar)
  - `MsTabBar` (see Phase 2)
- Delete `MsColors`, `PartnerColors` and the emoji strings in `MsEmpty` once nothing uses them.

**Done when:** `flutter analyze` is clean, the widget tests pass, and the old screens still compile.

## Phase 3 — Home: the room plus the «Сегодня» sheet

### Layout

- The scene is defined on a **390 × 440** canvas (the coordinates used below).
- Render it at the screen width, height = width × 440/390, and clip it to width × 430/390 centred, so 5 units are cut from the top and from the bottom.
- The «Сегодня» sheet starts at scene-y **392** (× scale). Build it as a `DraggableScrollableSheet` (or a sliver equivalent) that can be pulled up over the room. Background `ground`, radius 20 at the top, `shadowSheet`, 10 px grab handle.

### Animations

Respect `MediaQuery.disableAnimations`: no flicker and no perk when it is set.

- **Flame flicker:** origin (152, 223); 2.4 s loop, ease-in-out. Keyframes:
  - 0% / 100%: scale (1, 1), rotate 0
  - 30%: (0.94, 1.06), −2°
  - 55%: (1.04, 0.96), +1.5°
  - 80%: (0.97, 1.03), −1°
- **Dog perk** on tap: origin (357, 306); 1.1 s. 35%: rotate −5°, translateY −4. 65%: rotate −2°, translateY −2. Then back to rest.

### Candle domain (core, additive)

Add `CandleRepo` in `core/lib/src/domain/delight.dart` on top of the `ritual` replica, with tests. One entity `candle:shared` with these fields:

- `litBy`, `litAt` — written when someone lights it;
- `outAt`, `outBy` — written when someone puts it out;
- `seen:<deviceId>` — written by the partner's device when the light reaches it.

Derived state:

| State | Condition |
|---|---|
| `off` | no `litAt`; or `outAt` > `litAt`; or local midnight has passed since `litAt` |
| `pending` | lit by me, no `seen:<partner>` yet |
| `partner` | lit by the partner |
| `both` | lit by me and seen by the partner |

When a merge brings in the partner's light, show a local notification «София зажгла свечу» (one short vibration, its own Android channel «Ритуалы»).

Status row under the greeting: `flameSoft` background while lit, `surface` while out.

| State | Title | Meta |
|---|---|---|
| partner | «Свеча горит · зажгла София» | «21:14 · погаснет в полночь» |
| pending | «Горит у тебя» | «◐ у Сони загорится при связи» |
| both | «Горит у обоих» | «Соня увидела · 21:16» |
| off | «Свеча не горит» | «нажми на свечу — загорится и у Сони» |

### Weather (decision #10, keep it swappable)

- `WeatherRepository` interface; `OpenMeteoWeather` implementation:
  `GET https://api.open-meteo.com/v1/forecast?latitude=..&longitude=..&current=temperature_2m,apparent_temperature,weather_code,is_day,wind_speed_10m&hourly=temperature_2m,weather_code&forecast_hours=18&timezone=auto`
- Map WMO codes to kinds: 0–1 clear, 2–3/45/48 cloudy, 51–67/80–82/95–99 rain, 71–77/85–86 snow.
- Send the **city** coordinates only, never GPS. Cache the last result as JSON with its timestamp and refresh every 30–60 min while the app is in the foreground.
- Offline: show the last result with the meta «в 18:40». If there was never a result, draw the sky by clock and show no text.
- The weather sheet:
  - eyebrow «МОСКВА · СЕЙЧАС»;
  - PT Serif 48 temperature next to the condition;
  - meta «ощущается как +4° · ветер 5 м/с»;
  - a 6-column hourly row of `surface` tiles (time / temperature / word);
  - source line «Open-Meteo · по городу, без геопозиции · обновлено 21:00».

### Sheet content, top to bottom

1. Greeting row:
   - left: `roomGreeting`-style PT Serif 26 bold — «Доброе утро / Добрый день / Добрый вечер / Доброй ночи, <addressName>»;
   - right: `MsSyncStatus`; tapping it opens the sync sheet.
2. Candle status row (above).
3. `MsEyebrow` «Сегодня · четверг, 8 октября» with the `link` «Календарь ›», then up to three `EventRow`s (today, then upcoming). Tapping a row opens Calendar with that day selected.
4. «Карты под рукой»: the top-3 favourite cards as 112×64 tiles. A tap opens the full-screen card.
5. «Копилка»: the leading piggy bank as a compact card (name, %, split bar, amount). A tap goes to «Вместе».
